# M1/M3/M5 与 M2/M4 工具实施计划

用户已批准直接实现软件范围；没有 SDK/真机/资产，全部验收之前不发布 v0.2。

## 共同约束
Python 3.12、Pixi 锁定依赖、中文文档；保留 M0；只执行离线/合成流程。三个独立 Git 仓库，Bench/Ecosystem 固定 Core Git 提交。真实硬件审批不能由工具自授予。无版本标签、Release 或伪造设备支持。网站仅更新实际进展。

## 模块与接口
1. Core `roboidf/workflow.py`：持久化运行状态、预算、离线审批、工具注册、失败与恢复。仅依赖已有 core.py；提供模块CLI/demo，测试中断恢复、错误输入、预算、并发/状态篡改拒绝及审批边界。
2. Core `roboidf/backends.py`：SciPy least_squares 有界参数优化，数值诊断、激励设计，保留验证集拒绝。函数与模块CLI明确区分同模型离散基线和 solve_ivp 连续系统仿真。Bench 独立比较基线/优化器、噪声/失配/无激励情况，固定最终测试集，不反馈调参。
3. Core `roboidf/validation.py`：版本化机器人描述/离线Adapter元数据验证、真实硬件预检查拒绝缺字段、MJCF/XML和USD文件验证边界、两个回放轨迹的动态误差比较。接口声明不是硬件驱动或动力学认证。
4. Ecosystem `registry.py`、examples：显式注册离线插件，验证合同、来源与证据，拒绝重复/不支持版本/缺失来源/把离线证据当真机等级；复用Core合同，不能自动加载任意路径代码。
5. 根协调：依赖只由主代理修改；各模块独立测试，合并后全部测试与新克隆运行，审查后push；更新README/总览/网站进度，发布网站，不发布v0.2。

## 验收
现有M0回归全部保留。每模块有demo和失败测试。成功报告严格JSON与输入哈希、版本、种子/配置。失败非零退出或结构化拒绝，不输出成功标签。CI运行全部test及新增demo。硬件状态始终 pending，模型结构检查不等于跨引擎通过。
