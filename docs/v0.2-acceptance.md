# v0.2 / M0–M5 验收清单

2026-11-01：发布准备，尚未发布 v0.2。用户要求覆盖 M0–M5 并更新现有网站。

| 阶段 | 当前证据 | 尚需实现与验收 |
|---|---|---|
| M0 | 合成标量数据合同、拟合、回放、测试与 CI | 扩展机器人描述、能力与数据合同；保留现有回归 |
| M1 | 线性离线阶段记录 | 持久化运行状态、类型化工具、插件注册、失败恢复、预算与审批记录；中断恢复测试 |
| M2 | 无真机证据 | 型号/固件/SDK确认、Tianji/Wuji真实适配、设备时钟与反馈标定、安全限幅和独立停止机制、受控采集与故障演练 |
| M3 | 两参数合成最小二乘 | 经核对的成熟后端集成、可辨识性诊断、实验设计、基线对照、独立数据验证 |
| M4 | 无机器人模型或跨引擎证据 | 真实装配与坐标标定、MJCF/USD资产、参数映射、独立加载与动态回放对照；不能用模型能打开代替验证 |
| M5 | CSV示例、贡献指南、社区门户 | 版本化适配器模板与注册、兼容性验证、资产来源/许可检查、外部设备接入证据 |

## 待提供条件

- Tianji Arm / Wuji Hand 2 SDK、准确型号及固件；本机连接配置路径。
- 已授权的离线数据、机器人描述与 Mesh 来源；双臂/手装配标定。
- 真机实验范围、执行负责人、停止方式和环境约束。通用开发请求不等于运动授权。
- 用户已确认资源暂无，且必须全部 M0–M5 验收之后才发布 v0.2；本次仅推送开发提交并更新网站实际进度。

## 发布门槛

三个仓库独立 Pixi 锁定安装与全部测试通过；demo及故障场景回归通过；兼容依赖固定；版本、变更日志和支持矩阵一致。Release 与网站仅列实际完成及验证的能力。未通过硬件/数字孪生验收时不得宣称 M0–M5 全部完成。

## 实施顺序

先补 M1 状态、工具与插件接口，再完成 M3 离线/仿真后端及 Bench 对照；同步推进 M5 模板和兼容性工具。M2/M4 在设备、模型和验证条件确认后接入。最终统一版本、发布 GitHub Release、更新现有 Sites 门户并验证部署。
